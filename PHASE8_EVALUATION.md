# Phase 8 — Testing and Evaluation Report

## Scope and claims

This evaluation measures requirement matching on a small, synthetic, hand-labelled dataset and records existing application regression-test coverage. It does not measure or predict hiring outcomes. All resume and job-description text in the evaluation dataset is synthetic; no real personal resume data is used.

## Dataset

The evaluation contains 11 resume/job-description pairs in [`backend/tests/evaluation/dataset.py`](backend/tests/evaluation/dataset.py). Each case contains a structured resume, parsed job requirements, a relevant/irrelevant pair label, expected matched, partial, and missing required skills, and manually labelled evidence quotes with source sections. The dataset tests check that each quote exists in its declared synthetic source.

Coverage includes exact skill matches, aliases and abbreviations, evidence in experience bullets, a semantic partial match, partially relevant roles, irrelevant roles, misleading company-name overlap, Java/JavaScript substring overlap, junior/senior experience differences, all-missing requirements, and education mismatch. Cases are intentionally small and diagnostic; they are not a representative labour-market sample.

## Method

The improved engine and keyword baseline receive the same structured resume and required skills. Both runs use the same deterministic Jaccard word-overlap function for semantic comparisons; no network or embedding model is used. The baseline lowercases the resume corpus and checks literal substrings. The engine applies the project skill normalizer and its match/evidence logic.

For each case, a required skill is a true positive (TP) when predicted matched and labelled matched, a false positive (FP) when predicted matched but labelled missing, and a false negative (FN) when labelled matched but not predicted. Precision = TP/(TP+FP), recall = TP/(TP+FN), and F1 = 2PR/(P+R). Macro scores average case-level values; micro scores sum TP/FP/FN across all requirements before calculating the formulas. When a prediction set is empty, precision is defined as 1.0 to avoid division by zero; this can raise macro precision on irrelevant cases, so micro values are also reported. Partial engine matches are excluded from strict match metrics and should be interpreted as neither confirmed match nor confirmed absence.

Evidence localization recall checks whether the engine's reported source-section labels include the manually labelled section for each expected matched skill. This checks source-section localization, not semantic quote quality.

Latency uses `time.perf_counter()` around the synchronous engine and baseline calls during one sequential pass. Python allocation peak uses `tracemalloc`; it excludes native libraries and OS memory. These are local microbenchmarks, not production load tests. P95 uses the nearest-rank percentile (ceil(0.95 × n), one-based).

Ranking quality is **not evaluated**. The dataset pairs each candidate with a different JD and does not contain multiple candidates for one shared JD with ranking relevance labels. The current evaluator therefore cannot support a meaningful rank correlation or nDCG score.

TC11 was detected as a partial match and is excluded from strict match precision/recall positives; it is shown separately in the JSON case record. This is not match accuracy: TC03's Python evidence quote is present in an experience bullet, but the engine did not match Python there. The misleading company-name overlap TC06 also produces an engine false positive for Java. Both failures remain visible in the case results; the report does not conceal them.

Observed local timing and allocation values are machine-dependent and are recorded in `results.json` alongside Python version/platform. They should be quoted from that file for a specific run, not generalized as service-level performance.

For the recorded run on Windows 11 / Python 3.12.0, the engine mean/median/P95 were 1.4610 / 1.0973 / 5.3616 ms; baseline mean/median/P95 were 0.0179 / 0.0181 / 0.0235 ms. The peak Python-traced allocation during the one dataset pass was 50,360 bytes. These are measurements from one run (not estimates), have no warm-up or confidence interval, and the engine intentionally performs more work than the substring baseline.

## Regression test coverage

The existing test suite includes tests for:

- PDF parsing, invalid/malformed PDF bytes, empty upload, 5 MiB upload limit, and parse-service failure.
- Signup/login validation, invalid/tampered tokens, unauthenticated requests, and cross-user authorization for resumes, tailoring, PDF export, and tracker records.
- Tailoring success, validation failures, missing/foreign resume IDs, and mocked AI behavior.
- PDF export response type and download headers.
- Application tracker create/list/filter/update/delete, invalid values, and user isolation.
- Synthetic evaluation dataset schema and evidence-label consistency.

All AI calls in API tests use mocks, so tests do not need a live Claude credential. See `backend/tests/test_auth.py`, `test_resumes.py`, `test_tailor.py`, `test_export.py`, `test_tracker.py`, and `test_edge_cases.py`.

## Limitations

The sample has only 10 hand-authored pairs and cannot establish general real-world performance. Some expected labels are deliberately adversarial. Synthetic evidence labels are useful for regression testing but do not validate how a PDF parser or Claude will behave on varied real documents. The deterministic similarity function isolates evaluator repeatability; it does not fully represent production embedding-based similarity. Runtime numbers are single-run local measurements without concurrency, warm/cold repetition, confidence intervals, or external resource monitoring. Matching quality is document evidence alignment only, not candidate ability or hiring probability.

## Reproduction

Use Python 3.12 and the project's installed dependencies. From `backend`, run the evaluation command shown above. It writes detailed case decisions, aggregate metrics, evidence localization, runtime observations, and environment metadata to `tests/evaluation/results.json`. Run the full pytest command separately for regression checks. No API key or external service is required for the evaluation script or mocked tests.
